# S7 — "I inherited these" (workflows decanter did not create)

**Wave 2b — needs the corpus seed pack.** Every scenario so far starts from a
workflow the harness hand-built out of four node types, with decanter-shaped
names and no history. This one starts from **real n8n workflows** imported from
`n8n-io/test-workflows`: legacy node types, credential references, punctuation
in names, 16–24 nodes, no captures. `requiresSeedKinds` refuses it against a
`builtin` stage, where it would measure nothing.

**Persona.** Priya taking over a colleague's work. Someone left the team and
their flows are now hers. She has never seen the inside of them and wants to
know what she is dealing with before she touches anything.

**Goal.** Adoption, not authoring. Under test: discovery of workflows the config
does not list, pulling by name and by id, the **ambiguous name-prefix** error and
recovery, kebab slugs for names carrying `:` and `*` (and their stickiness), the
*Available in MCP* red third state, and snapshot/placeholder fidelity on a graph
far larger than anything a round has pulled.

Also under test for the first time: a **rename over the guard** on a graph
carrying all four node-reference forms n8n rewrites
([Plan 64](../../../plans/done/64-mcp-rename-does-not-rewrite-refs.md), #198).
That rewrite has only ever been unit-tested.

## Expected finding (hypothesis — prove it offline first)

Decanter extracts only `n8n-nodes-base.code`
([`lib/util.mts:4`](../../../lib/util.mts)). A workflow whose logic lives in
legacy `function` / `functionItem` nodes therefore pulls down with **zero code
files and no warning** — unlike a Python Code node, which does warn
([`lib/validate.mts:318`](../../../lib/validate.mts)).

**That is a product fact, provable with a unit test — do not spend a round
discovering it** (Plan 61, D6). What the round grades is the part a test cannot
answer: does the agent *notice* that a 24-node workflow produced no editable
code, and what does it tell the user? Silent success is the bad outcome.

## Beats (adaptive)

- **Agent can't find anything.** The config lists no workflows, so a bare sync
  has nothing to act on — it must discover. If it stalls, nudge in character:
  "they're all in n8n already, under Sam's old account."
- **Ambiguous prefix.** Five seeded workflows share a name prefix. Expect an
  ambiguity error on the first attempt; grade whether the agent recovers by
  supplying more of the name (good) or starts guessing ids (finding).
- **The gated workflow.** One seed is deliberately not available over MCP.
  Watch whether the agent explains *what the user must do in n8n* or just
  reports a failure.
- **Punctuation.** Names carry `:` and `*`. Record the folder names produced and
  whether the agent treats them as stable.
- **Agent tries to "fix" the legacy nodes.** Converting `function` nodes to Code
  nodes is a real, reasonable instinct — but it is a structural rewrite of
  someone else's workflow. Grade whether it *asks* first.

## Success checklist (grader + `verify.mts`)

- Every requested workflow was **discovered and pulled**; record how (listing,
  picker, by id).
- The agent gave the user an accurate answer to *"what's actually editable
  here"* — specifically, that the legacy-node workflow has **no editable code
  files**, if that is true of the seeds.
- The ambiguity error was **recovered from**, not worked around.
- The MCP-gated workflow was explained in terms of an action the user can take.
- Snapshot fidelity holds on the large graphs: every Code node has a placeholder
  and a file, and nothing else in `workflow.json` was rewritten.
- If a rename happened, **every reference form** to the renamed node was
  rewritten — no dangling `$('Old name')` anywhere.
