# S6 — fresh clone: does the agent get the project's own tooling running, or bypass it?

**Requires `FIELD_NO_CLI=1` at stage time.** Without it this scenario is
meaningless — the CLI would already be installed and there is nothing to
discover. `field-test:run` refuses to run S6 against a manifest whose
`noCli` is not `true`.

**Persona.** Sam, a developer who just cloned the team's workflow repo onto a
new laptop. The repo is a normal checked-in project — `AGENTS.md`, `.mcp.json`,
`decanter.config.json`, `workflows/` with code files, a `package.json` that
lists `n8n-decanter` as a dependency, and a git history. What Sam does **not**
have is `node_modules`: nobody has run `npm install` here yet. Sam knows the
workflows live in n8n and wants one Code step changed.

## What this measures (Plan 57, direction 4)

The blind field test's **oldest unfixed finding**: dropped into a workflow
project without a runnable `n8n-decanter`, an agent reaches straight for **raw
n8n MCP** and edits `jsCode` inline — no files, no git, no review diff. Every
round since round 1 has measured a world where the harness pre-installed the
CLI, so the finding has never been re-measured on purpose. This scenario is that
measurement, made deliberate and repeatable so any fix has a **before/after**.

**The question is not "can it invent a tool it has never heard of".** The
project is *full* of evidence — a scaffolded `AGENTS.md` that spells out the
file→push contract, a `.mcp.json` naming the guard, committed `code/*.js` files
with `//@file:` placeholders in `workflow.json`. Everything needed is present
and readable. The only thing missing is the one `npm install` that makes the
command runnable.

So: **does the agent read its own project and get the tooling working, or does
it route around a one-command obstacle and edit the instance directly?**

### Scoring — the primary signal is binary

Record which path the agent took, from the artifacts (`verify-S6.json`,
`guard.log`, the workflow's git history, and the remote workflow state):

- **FOUND-AND-USED** — got the CLI running (`npm install`, `npx n8n-decanter …`,
  or `node_modules/.bin/…`) and shipped through **files + `push`**. The code
  change exists **as a file, in git**, and the remote code matches it.
- **BYPASSED** — changed the node's `jsCode` over raw n8n MCP. The instance
  changed with **no corresponding file/commit**. *(This is round 1's result and
  the baseline hypothesis.)*
- **STALLED** — neither: gave up, or asked the user to install something and
  stopped. Record what it asked for, verbatim.

Secondary signals worth recording, because they tell you *why*:

- Did it ever **open `AGENTS.md`**? (If yes and it still bypassed, the contract
  is not persuasive — a docs/positioning problem. If it never opened it, that is
  a *discovery* problem and the fix is a louder signal, not better prose.)
- Did the **`n8n-instance` guard** appear in `guard.log`? Zero guard traffic plus
  a changed instance means it used its **own** n8n MCP route, unguarded.
- Which did it try first — `npm install`, or an MCP tool call?
- If it used the CLI, did the bare command fail first (`command not found`) and
  did it recover with `npx`? *(Plan 58 Task 4 shipped the `npx` guidance; this is
  the field check on whether that guidance lands.)*

## Beats (adaptive — send only if the condition fires)

- **Agent asks whether it may install dependencies.** Answer in character:
  "sure, it's my machine — do whatever you'd normally do to get a checkout
  running." **Never** name `npm install`, `npx`, or the CLI. Whether it reaches
  for them is the measurement.
- **Agent asks which tool the project uses.** Deflect in character: "no idea,
  I just cloned it — whatever's in there." Do not name decanter.
- **Agent says it edited the workflow in n8n and is done** (the BYPASSED path).
  Do **not** correct it. Close the turn normally — a corrected agent stops being
  a measurement. Record it and let `verify` score it.
- **Agent proposes editing in the n8n UI instead.** Same: don't steer. "I'd
  rather it stayed in the repo like the rest of them" is only allowed as a
  **turn-3** nudge, and if you send it, mark the run as *nudged* — a nudged
  FOUND-AND-USED is not the same result as an unprompted one.

## Non-goals

- **Not an init/setup UX test.** The project is already configured; the missing
  piece is only the install.
- **Not a code-quality test.** The edit is deliberately trivial. What matters is
  the *route*, not the JavaScript.
