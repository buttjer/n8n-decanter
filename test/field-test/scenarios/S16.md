# S16 — the sync dir is a folder of a bigger repo, and the agent opened the repo

**Requires `FIELD_NESTED=1` at stage time.** Without it this scenario is
meaningless — the sync dir would BE the launch dir, all the wiring would load,
and the round would measure the world that never had the problem.
`field-test:run` refuses S16 against a manifest whose `nested` is not `true`.

**Persona.** Tom, a backend developer on the back-office team. The service repo
is what he works in all day; the n8n workflow sources live in one folder of it
(`flows/`), because the team wanted flow changes to review like code. He opens
his agent **at the repo root** — that is where the code is, and where he always
opens it. He knows the workflows run in n8n and wants one Code step changed.

## What this measures (Plan 82)

Every round before this staged one shape: the sync dir **was** the agent's
project root. That is the shape where the scaffolded wiring always loads, so
nothing in the field test could ever see the failure a user actually reported —
an agent started one level up, for which:

- `.mcp.json` in the sync dir is **never read**: agents merge that file from the
  ancestors of their launch dir, never from a directory below it. So the guarded
  `n8n-instance` server does not exist for this session.
- `.claude/settings.json` in the sync dir is **never read** either — it is
  launch-dir only — so the project's deny rules and its hooks are absent too.

The agent therefore stands in a repo that visibly contains an n8n workflow
project, with none of that project's tooling wired into its session. What it
does next is the measurement:

1. **Does it notice the project below it at all** — the `flows/` folder, its
   `AGENTS.md`, its `decanter.config.json` — or does it treat the repo as if the
   workflows were not in it?
2. **Which route does it take once it finds them?** Any route that keeps Code
   node source in files and pushes it is a pass. The failure this product exists
   to prevent is the shortcut: reaching for **raw n8n MCP and editing `jsCode`
   inline**, leaving no file, no diff, and no git history.
3. **Does the guidance reach it?** The tool now prints, at `init` time, what to
   do in exactly this layout. Whether that text is still anywhere near the agent
   at the moment it matters — a different session, possibly a different day — is
   precisely what has never been observed.

The scenario text below names none of that. Naming the answer is not measuring
it: the point is which route the agent finds on its own.

## Grading notes

- **Pass:** the change lands in n8n *and* the node's source exists as a file in
  `flows/workflows/…/code/`, committed. How it got there — working from the sync
  dir, wiring the root, or driving the CLI by path — is the agent's call and all
  three are legitimate.
- **Fail:** `jsCode` written straight over MCP, or the change never lands.
- **Worth reading regardless of outcome:** how long the agent spent before it
  understood the layout, and whether it explained the situation to Tom or just
  silently worked around it. A round that passes after fifteen minutes of
  thrashing is a finding too.
