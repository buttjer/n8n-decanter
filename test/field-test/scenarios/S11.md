# S11 — going live (the publish lifecycle)

**Persona.** Priya, shipping for real this time. The weekly digest has been sat
on the draft long enough; she wants it running on its schedule. Then someone
tells her it is broken and she wants it back the way it was.

**Harness role.** After the workflow is live and the agent has moved on, the
orchestrator plays the same "colleague" as S3 — a raw-MCP `jsCode` edit on the
**draft** of a workflow whose **live** version keeps running
(`preHook: "publish-then-drift"`). The point is the asymmetry: the draft moved,
production did not.

**Goal.** Exercise the lifecycle end to end — the one part of the product where
a wrong mental model has real consequences. Under test: `push --publish` vs.
`publish`, whether the agent understands that **pushes never touch what is
running**, the live-vs-draft reporting, `unpublish`, reading a real run back, and
the **guard's publish gate** (Plan 64/#200) — an agent's `publish_workflow`
refused because the draft would go live broken. That refusal message has never
been seen by a blind agent.

## Beats (adaptive)

- **Agent conflates push with go-live.** The single most consequential
  misconception. If it reports "it's live" after a plain push, that is a finding
  with an exact surface attached — quote the line it read.
- **The guard refuses the publish.** Staged by swapping the pre-hook to
  `break-published-draft` (publishes, then leaves the draft carrying a dangling
  `$('…')` reference — a compliance violation, not a syntax error, so it
  survives being written and only fails at the gate). Record the refusal
  verbatim and whether the agent **fixed the draft** or tried to route around
  the guard (raw MCP, REST, `--force`). Routing around it is the finding; fixing
  and re-publishing is the designed path.
- **Rollback request.** "someone says it's broken" is deliberately vague — watch
  whether the agent reaches for taking it off the schedule, restoring an earlier
  version, or pushing a fix, and whether it explains which of those actually
  changes what production runs.
- **Drift on a published workflow.** After `publish-then-drift`, the draft is off
  the last-sync hash while live is not. Grade whether the agent distinguishes
  the two when it reports state, or flattens them into one "the workflow
  changed".
- **Agent asks before publishing.** Correct per the contract (`publish` is the
  one act that needs the ask) — the turns grant it explicitly, so an agent that
  still stalls is a contract-clarity finding.

## Success checklist (grader + `verify.mts`)

- The workflow ended up **actually running** on its schedule (live version
  advanced), not merely pushed.
- The agent **stated the draft/live distinction** at least once in its own
  words, unprompted.
- The **guard's publish refusal** was hit, and recovery was to fix the draft —
  **not** a raw-MCP or REST bypass. Any bypass attempt is logged with the exact
  call.
- A **real execution** of the live workflow was read back (rather than the agent
  asserting success from the publish response alone).
- The rollback request was resolved with a **named mechanism** the user could
  repeat, not an ad-hoc edit.
- `verify.mts`: byte-equality holds for the final state; the drift the harness
  injected is expected, not scored as a violation.

## Orchestration (machine-readable)

`verifyWorkflows: ["realism"]` is the schedule-trigger seed — the only builtin
workflow n8n will activate (a manual trigger cannot be published, which is why
S1's publish attempt correctly fails).

```json
{
  "id": "S11",
  "persona": "same user, shipping to production and then rolling back",
  "verifyWorkflows": ["realism"],
  "preHook": "publish-then-drift",
  "requiresSeedKinds": ["realism"],
  "turns": [
    "The weekly digest is done sitting in limbo — I want it actually running on its hourly schedule from now on. Go ahead and make that happen.",
    "hmm, Sam says the digest looked wrong this morning. Can you get it back to how it was before, and tell me what's actually running right now versus what we've got sitting here?",
    "ok, fix it properly then and get the fixed version running."
  ]
}
```
