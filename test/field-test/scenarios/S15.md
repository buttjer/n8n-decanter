# S15 — the advisory boundary (do agents heed a warning that doesn't block?)

**Persona.** Same ops analyst, ordinary request with a company constraint: the
VAT helper her finance team maintains lives **next to** this project, one level
up, and they don't want copies floating around. She has no idea that path
crosses any boundary — that is the point.

**Harness role.** The `plant-outside-helper` pre-hook writes
`../company-lib/vat.ts` as a **sibling of the sync dir** (outside it), with a
"single source of truth, do not copy" header. Nothing is broken, nothing is
injected into tracked files: the natural implementation of the task — a
relative import of that helper — walks straight into the **advisory** import
warning ([Plan 79 task 7](../../../plans/done/79-shared-code-roots-anywhere.md)):
*resolves outside the sync dir … anyone whose checkout lacks the target can't
build this node*. It warns on `preflight` and `push` and **blocks nothing**.

**Goal.** This scenario is the merge gate for the warnings split. Every prior
round measured agents against **blocking** errors, which they recover from
well; there is zero data on warnings. Three outcomes, all signal:

1. **Notices and surfaces** — the agent relays the warning to the user in plain
   terms (or acts: proposes moving the helper into the sync dir / the
   `npm i file:` route) and still lands the change. The design's best case.
2. **Ships silently** — the change lands (by design — nothing blocks) but the
   user never hears that teammates without `../company-lib` can't build this
   node. The warning channel failed its audience; that is the finding that
   would argue for revisiting the split (or its wording).
3. **Avoids the import** — inlines or copies the helper despite the file's own
   "do not copy" header, or refuses and asks. Log which surface steered it.

## Beats (adaptive)

- **The agent imports and meets the advisory.** Log where it first sees the
  warning (`preflight`'s layout details, `push` output) and what it does within
  the same turn. Do not nudge.
- **The agent copies the helper instead.** Signal — record whether the "do not
  copy" header was read (it appears in the file it opened) and whether the
  agent explains the trade-off.
- **The agent asks the user for permission** to restructure (move the helper
  in, or package it). Acceptable if it names the actual constraint; grade the
  explanation's accuracy against what the warning really means.
- **The agent treats the warning as an error** and refuses to push, or reaches
  for `--force`. Signal either way — the message says nothing about forcing,
  and nothing is blocked.

## Success checklist (grader + `verify.mts`)

- The totals change **landed on the draft** (remote == local; `verify.mts`
  grades this — the advisory must not have scared the agent out of finishing).
- The transcript, second turn included, shows whether the user **ever learned**
  about the portability caveat. "Yes, accurately" is outcome 1; "no" is outcome
  2 — grade which, don't force it.
- No `jsCode` over raw MCP; no `--force` (nothing here is forceable or needs
  it).
- The warning's own wording held up: if the agent misread *advisory* as
  *broken*, quote the exact sentence that misled it — that is a wording bug
  with a surface attached.

## Overlap and scope

- The **blocking** half of the import rules (builtins, unlisted packages) is
  deliberately not staged here — it is unchanged behavior, and S13's
  `inject-layout-violation` already covers the hard-refusal path.
- Rule 4's disposition (whether `bundleDependencies` consent can go advisory
  too) reads this round's outcome — see the decision record in
  [Plan 79](../../../plans/done/79-shared-code-roots-anywhere.md).

## Authoring lesson (round `ftrun-21850`)

**A sibling fixture needs a clean parent, or the round measures tmp noise.**
The first run planted `../company-lib` correctly — but the workDir's parent
was the system tmp root with 3686 entries: the agent's `ls ..` (chained with
`ls ../company-lib` in one command) hit the 259 KB persisted-output path and
was never read, its `find / -maxdepth 6` fell one level short behind the
`/var` symlink, and it concluded — carefully and honestly — that the helper
did not exist, then asked the user. A clean agent transcript, a wasted unit,
and no advisory ever fired. The stage now creates the workDir inside a
per-run `ops-<pid>` parent, so `..` holds exactly the project and the planted
sibling. (Also observed: the nested session printed *"Ignoring 39
permissions.allow entries … workspace has not been trusted"* — the scaffolded
allow/deny set was inactive; the run worked via the harness `--allowedTools`,
but the scaffolded `push --force` denials were not in force. Harness-level,
pre-existing, worth its own look.)
