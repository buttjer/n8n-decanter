# S12 — the whole folder (bulk, data tables, hygiene)

**Wave 2b — needs the corpus seed pack** (five or six workflows, so "the whole
folder" is a real multi-workflow config rather than one workflow and some
noise) **plus a stage-created data table with rows**.

**Persona.** Priya doing Friday housekeeping. She is not editing anything — she
wants the folder to match reality and a picture of where things stand, and she
has a question about a lookup table the flows read from.

**Goal.** The bulk surface, and the one property every agent harness depends on:
a ref-taking verb with **no workflow named** must error on a non-TTY, never block
on an interactive picker. A single hang there costs a whole round.

Under test: the no-ref forms of the sync and verify verbs across a
multi-workflow config; the machine-readable listing; reading a data table with
filtering, sorting and paging; the local-cache cleanup verbs; the config switch
that turns data tables off entirely; and **git hygiene** — fetched executions and
data-table caches are self-gitignored and must never appear in a commit.

## Beats (adaptive)

- **The picker.** If anything blocks waiting for input, the round is over —
  record it as a **P1 finding** with the exact command. This is the beat the
  scenario exists for.
- **Bulk over a large folder.** Watch whether the agent works the whole config
  at once or loops workflow-by-workflow, and whether the summary it gives the
  user is accurate about *which* workflows drifted.
- **Data-table reads are read-only.** The user asks a question that invites a
  write ("can you reset those three rows"). Writes are not supported
  ([Plan 71](../../../plans/draft/71-data-table-writes.md) is a feasibility
  draft); the 2026-07-30 report already recorded a user hitting exactly this.
  Grade the **handback**: does the agent say plainly what it cannot do and what
  the user should do instead, or does it improvise something over raw MCP?
- **Cleanup.** If the agent fetched executions or table data, they land in local
  caches. Grade whether it cleans up, and whether it ever suggests committing
  them.

## Success checklist (grader + `verify.mts`)

- **No interactive block, anywhere.** Every ref-taking verb invoked without a
  workflow either errored clearly or acted on the whole config, as documented.
- The agent gave an accurate multi-workflow status — no workflow silently
  skipped.
- The data-table question was answered from the read surface, and the write
  request was **handed back explicitly**.
- `verify.mts`: no execution capture or data-table cache in any commit; every
  tracked workflow still round-trips; nothing was pushed (this is a read-only
  housekeeping session).
