1	# n8n-decanter — guide for coding agents
2	
3	This is the **source of truth** for working in this repository, and it is written to
4	be tool-agnostic. Codex and opencode read this file natively; Claude Code reads it

7	
8	This repo holds the **Code-node source** of n8n workflows *decanted* into
9	git-friendly form: one folder per workflow containing a read-only
10	`workflow.json` structure snapshot plus a `code/` subdir with one source file
11	per Code node. The `n8n-decanter` CLI syncs the code with the live n8n
12	instance over n8n's **MCP server** (`pull` / `push` — draft-first, code-only).
13	This document is the contract for creating and editing these files.
14	
15	## The short version
16	
17	- **Code lives in `code/`, never in `workflow.json`.** A node's `jsCode` is only
18	  a `//@file:code/<name>` placeholder — edit the file it points at.
19	- **Code-node source is authored HERE and synced by decanter — never edited on
20	  the n8n instance directly** (not in the UI, not via MCP tools, not via n8n
21	  skills). The git files are the single source of truth for code.
22	- **Workflow structure has no editable file here — it lives in n8n.**
23	  `workflow.json` is a read-only snapshot for review and offline tooling; you
24	  restructure a workflow over the guarded MCP surface (below), not by editing
25	  it — editing it changes nothing remotely
26	  and the next `pull` overwrites it. Make structure changes in the n8n editor
27	  or through n8n's own MCP tools (the scaffolded `n8n-instance` MCP server is
28	  the guarded route) — creating and renaming workflows, adding/renaming/wiring
29	  nodes, archiving. `pull` reconciles the local mirror afterwards.
30	- **Never hand-edit `.decanter.json`, and never write a `// @ts-n8n sha256:`
31	  marker.** These are machine-owned; touching them corrupts sync state and the
32	  CLI blocks it at `push`.
33	- **Orient before you edit: run `preflight` at the *start* of a task, not only
34	  before the push.** It is read-only. It tells you whether someone edited that
35	  code on the instance (`drift`), whether both sides moved (`CONFLICT`), and
36	  whether a push from an earlier session is still pending (`parity`). **On
37	  drift, `pull` and carry on** — a pull is part of the work. **On `CONFLICT`,
38	  stop and ask**: `diff` shows the lines before either side is overwritten.
39	  Nothing is lost if you skip this (`push` refuses to overwrite remote edits) —
40	  but the work may have to be redone on top of what you didn't know was there.
41	- **`push` writes the DRAFT and is part of finishing the work — code that only
42	  exists in this folder is not done. `publish` (or `push --publish`) changes
43	  what is actually running and needs the user's say-so.** The loop:
44	  **edit → `preflight` (grades local) → `push` → `test` (grades the draft — now
45	  your code) → `publish` only when asked.**
46
