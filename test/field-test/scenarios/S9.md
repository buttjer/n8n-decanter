# S9 — air-gapped day (the offline ladder) · host-only

**Host-only.** The local-engine replay runs the node in Docker, and `fs.watch`
dies under a sandboxed shell — so this scenario runs **unsandboxed on the host**,
never in `--container` mode.

**Persona.** Priya on a train with flaky wifi, or on a morning where n8n is
down. She has edits to make and no way to reach the instance, and wants to know
whether she can get anything useful done at all.

**Goal.** The offline half of the verification ladder — the part that
deliberately needs no instance and no credentials. Under test: the fully-offline
gate, the local-engine replay (with and without network, pinned to an n8n
version), the browsable run vs. the headless one, the **multi-batch loop**
preview-vs-hard-error split, running a single node against a fixture, and the
signposting for **instance-scoped globals** that a local run cannot resolve.

## Beats (adaptive)

- **Agent tries to reach the instance anyway** and reports failure. The
  interesting question is what it does *next*: the offline path is documented
  and one flag away. Record whether it finds it, and from where (help output,
  docs, the project contract).
- **Agent hits an instance-scoped global.** `$vars` / `$secrets` /
  `$evaluateExpression` cannot resolve locally. The CLI signposts the
  instance-side alternative; grade whether the message routes it or just reads
  as a crash.
- **Multi-batch loop.** A loop workflow previews in the browsable run but hard-
  errors headless. That asymmetry is deliberate and documented; grade whether
  the agent understands it is a limitation of the *preview*, not of its code.
- **Type error.** A deliberate one is present. Grade whether the agent finds the
  typecheck gate, and whether it reaches for the opt-out flag instead of fixing
  the error (that reflex is the finding).

## Known open defects — do not spend the round rediscovering these

- **`node run` ignores the branch index.** `all(1)` and `$items('X', 1)` return
  output 0's items, silently — [Plan 63](../../../plans/open/63-field-feedback-bugfixes.md)
  Task 5, with the pin-side half in
  [Plan 66](../../../plans/draft/66-multi-output-pins.md). If the seeds put a
  branching node in the agent's path, it will get **wrong data, not an error**.
  Land those fixes before running S9, or drop the multi-output beat: a round
  that "discovers" this is a round spent confirming a written-down bug.

## Success checklist (grader + `verify.mts`)

- The agent got **real work done with no instance** — a verified edit, not a
  "come back when you're online".
- It found the offline gate **without a nudge** naming it.
- Nothing reached the network: no instance call succeeded or was retried in a
  loop.
- The type error was **fixed**, not suppressed.
- `verify.mts`: nothing was pushed (there was nothing to push to); local state
  is consistent and every tracked file still round-trips.
