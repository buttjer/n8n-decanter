# S8 — "is it safe to ship?" (the verification ladder)

**Persona.** Priya again, but wearing her cautious hat. **Weekly revenue totals**
runs against real data every week and she has been burned by a bad deploy
before. She wants a change made *and* wants to be shown it still behaves —
before anything goes near production.

**The target is named outright, and that is a fix.** Turn 1 used to say "the
weekly digest flow" — but the `wave2` pack also seeds **Weekly digest roll-up**,
which matches that wording *better* than the intended `s8-ladder` workflow. Round
`ftrun-45973` duly picked the wrong one, found it had never run, and said so;
decanter answered truthfully for the workflow it was asked about, and the unit
FAILed for an authoring reason. Worse, it is a coin flip: `ftrun-38054` picked
the right one from the identical prompt. See `STYLE.md` — naming something the
pack seeds is only half the rule; the other half is that the name must not fit
anything *else* it seeds.

**Harness role.** The stage **executes the target workflow once** before the
round, so a genuine execution exists on the instance (`preHook:
"seed-capture"`). That is the difference from S2, whose scenario pins were
synthetic: here the capture has **real provenance**, so `scenario create
--execution` and the capture-diff path are exercised for the first time.

**Goal.** A code change lands, and the agent produces *evidence* the change is
sound. The value under test is the whole documented agent gate — `preflight`,
`scenario`, `executions`, `test` — which **no blind agent has ever run**, in
either its pre-Plan-59 or its current shape.

## Beats (adaptive)

- **Agent changes the code and declares victory.** If it reports "done" with no
  verification step at all, that is the headline finding — the scaffolded
  contract names the loop explicitly. Nudge once, at goal level: "before this
  touches anything real, can you show me it still does the right thing?"
  **Never** name a verb.
- **Agent runs the gate and reads only the score.** Watch whether it quotes the
  **coverage** block ("what this did *not* check") or treats a green line as
  proof the workflow runs. Misreading green as "verified live" is the exact
  claim the docs make and the exact thing nobody has measured.
- **Agent hits the scenario gap error.** Expected: authoring pins for an
  uncovered node hard-errors rather than silently filling zeros. Record whether
  the message got it to the fix in one hop. **What changed
  ([Plan 65](../../../plans/done/65-three-gate-scenario-mismatch.md)):** `check`
  used to report only the looser of two gates, so a green scenario could still be
  refused by `test` with no supported way out. Now `check` reports both and
  `scenario create --extend` closes the difference — so "green, then rejected"
  is a **regression** if a round sees it, not the known state.
- **Agent asks whether to push first.** In character: "yeah, put it where it
  needs to be — just don't flip it on for real yet."
- **Agent reaches for a removed verb** (`check`, `status`, `simulate`). Log the
  exact command and whether the removal hint landed it on the replacement in one
  hop — post-Plan-59 that is a discoverability finding, not verification.

## Success checklist (grader + `verify.mts`)

- A **verification step ran before any go-live** — record exactly which surface
  (`preflight`, its `--json` form, `node run`, `test`, `scenario check`) and in
  which order. This is the graded question.
- The agent **fetched the existing execution** rather than inventing input data,
  and any scenario it wrote carries **capture provenance** (not synthetic pins).
- The change reached the **draft** and the live version is untouched.
- `test` ran **after** the push (it grades the draft, so before-push is the
  documented mistake) — or the agent explained why it did not run it.
- **Nothing read-only mutated anything**: `versionId` is unchanged across every
  `preflight`/`diff`/`executions` call the transcript shows.
- `verify.mts`: byte-equality holds; `executions/` and `scenarios/` are
  structurally valid and the capture never landed in a commit.
