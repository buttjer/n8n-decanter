Usage: n8n-decanter <verb> [workflow…] [flags]
  Run with no arguments in a terminal for the interactive picker; `help` prints this.

Setup
  init [dir] [--force] [--host <url> --token <mcp-token> --api-key <public-api-key>]

  completion zsh|bash                     print a shell completion script for your rc file

Sync (over n8n's MCP server — Code-node source only; structure lives in n8n)
  pull [workflow…]                        pull code into workflows/<kebab>/ (default: config list)
  push [workflow…] [--force] [--publish] [--no-typecheck]   push code to the draft (--publish takes it live)
  watch [workflow]                        watch code/, push each save to the draft
  publish [workflow…]                     take the draft(s) live
  unpublish [workflow…]                   return the draft(s) to draft-only

Inspect & test
  preflight [workflow…] [--simulate] [--offline] [--json] [--fail-on=warn] [--fail-fast] [--require=<ids>]
                                              the gate: grades LOCAL code into one scored, read-only verdict
                                              --simulate ADDS a local-engine run (Docker); --offline DROPS instance reads
  diff [workflow…]                        per-node line diff, local code vs the n8n draft (always exits 0)
  executions [workflow…] [--status=…] [--limit=N]   fetch execution data (numeric arg = one by id)
  executions [workflow…] clean            delete fetched execution data (offline)
  data-tables [table…] [--filter=… --search=… --sort=… --limit=N --all]   fetch data-table schema + rows (read-only)
  data-tables [table…] clean              delete fetched data-table data (offline)
  test <workflow> [--execution <execution-id> | --scenario <slug>] [--trigger <node>] [--json]
                                              grades the INSTANCE's draft (after push). Bare: static check only,
                                              nothing runs. With --execution/--scenario: pinned run, exits 1 on divergence
  list [--remote] [--json]                pulled workflows: name, id, folder

Scenario (named, committed pin-data sets — captured or schema-scaffolded)
  scenario create <workflow> ["<slug>"] [--execution <id>] [--scaffold]   write a committed scenario from a capture and/or the workflow's schemas
  scenario create <workflow> "<slug>" --extend            top an existing scenario up with the nodes `test` still needs
  scenario check <workflow> ["<slug>"]                     structurally validate a scenario (or all); exits 1 on invalid

Backup (git-native, redeployable disaster-recovery store — REST, needs N8N_API_KEY)
  backup create <workflow>                  capture the workflow's full REST export into backups/ (not auto-committed)
  backup restore <workflow> [<backup>]      redeploy a backup as a NEW, unpublished workflow (node ids preserved)
  backup list <workflow>                    list retained backups: timestamp · versionId · node count

Node
  node run <node-file> [fixture.json] [--allow-env]  run a node locally (offline)
