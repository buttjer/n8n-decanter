# S10 — "our n8n died" (disaster recovery)

**Wave 2b — needs the corpus seed pack.** The workflows here carry **real
credential references** (8 and 14 of them), which is what makes the rebind path
after a restore real rather than theoretical. Nothing on the throwaway instance
can resolve them — that is the point.

**Persona.** Priya after a scare. The team's n8n went down for two hours last
week and nobody could say whether the workflows were recoverable. She wants a
copy she can put back, and then she wants to actually put it back.

**Goal.** The largest decanter-specific surface that **neither the harness nor
the 2026-07-30 production report has touched at all**. Under test: taking a full
export, the deliberate **not-auto-committed** warning that comes with it,
listing what exists, restoring, and what a restore produces.

## Beats (adaptive)

- **The uncommitted recovery point.** A backup is written but deliberately *not*
  committed, with a warning saying so. Three outcomes, all interesting: the
  agent reviews and commits it (good); it leaves the recovery point untracked
  and tells the user it is safe (the finding this beat exists for); or it
  commits a large full export without looking at it (a different finding).
- **`archive` vs `backup` confusion.** The wording trap Plan 35 already flagged.
  If the agent conflates "make me a copy" with archiving the workflow in n8n,
  record the exact phrasing that misled it.
- **Restore semantics.** A restore produces a **new, unpublished** workflow with
  node ids preserved; the source is untouched. Grade whether the agent knows
  that before it acts, and whether it tells the user — "put it back" plausibly
  reads as *overwrite the original* to an agent that has not read closely.
- **Credential rebind.** The restored workflow's credential references cannot
  resolve. The CLI emits hints; grade whether the agent surfaces them as
  *actions for the user* or buries them.
- **Backup pruning.** With the store pre-filled past the limit, an old backup is
  pruned. Watch whether the agent notices, and whether that is alarming to it.

## Success checklist (grader + `verify.mts`)

- A recovery point exists **and is in git** — or the agent explicitly told the
  user it is not, and why.
- The restore produced a **distinct workflow**; the original is byte-identical
  to before, and the restored one is **not published**.
- The agent named the **credential rebind** as a remaining user action.
- No full export was committed sight-unseen.
- `verify.mts`: source workflow untouched; restored workflow's node ids match the
  export; `backups/` contents structurally valid.
